# Решения и известные ловушки

Этот документ фиксирует причины, а не только текущее состояние. Меняйте решение
только вместе с тестами, документацией и явным объяснением новой причины.

## D-001. Целевой язык всегда русский

Sensemark автоматически определяет исходный язык, но не предлагает выбор языка
результата. Это сохраняет интерфейс быстрым и уменьшает вариативность prompt.

Следствие: выделение только на русском обрабатывается локально без карточки и
без API.

## D-002. Сначала локальная очистка, затем модель

DOM выделения может содержать скрытый дубль, подпись кнопки, перевод сайта
или управляющий символ. Передавать это модели дорого и
ненадёжно, поэтому доказанный структурный шум убирается в
`selection-text.js`.

Нельзя удалять текст только потому, что он выглядит необычно. Очистка должна
опираться на общий DOM-сигнал или управляющую категорию Unicode, а не на
правила под конкретный сайт.

Ссылки внутри абзаца — часть текста. Раньше все `<a>` считались интерфейсом,
и из перевода выпадали слова-ссылки (например, «France» в предложении о Париже).
Интерфейсом считаются только ссылки внутри меню, навигации и шапки/подвала
сайта.

## D-003. Несколько языков — структурированный ответ

Многоязычный перевод имеет секции с письменностью и языком, чтобы UI не
смешивал результаты. Русская часть остаётся без изменений.

Исключение: короткий параллельный заголовок на двух языках может быть переведён
один раз. Это предотвращает дублирование и лишний repair-запрос.

## D-004. Не показывать пустую карточку

Карточка на странице создаётся только после появления видимого перевода.
Служебная метка и пустой streaming scaffold не считаются видимым ответом.

Причина: пустое окно загрузки отвлекает и создаёт впечатление ошибки.

## D-005. Repair — не обычная часть перевода

Второй API-запрос расходует токены и увеличивает задержку. Он разрешён только
когда локальная валидация называет конкретную ошибку ответа. Нельзя использовать
repair для определения языка, улучшения стиля или исправления необязательного
форматирования.

## D-006. Неизвестные термины имеют отдельный UI

Имя, название, бренд, никнейм, опечатка или выдуманный термин не должны
выглядеть как обычный перевод. `[[reference]]` включает отдельную янтарную
карточку, категорию и осторожное объяснение. Обычное словарное слово вроде
`Why` всегда предпочитает перевод, даже с заглавной буквы.

## D-007. Toolbar popup остаётся компактным Chrome popup

Ручной перевод реализован обычным HTML/CSS/JS без React. Chrome вычисляет
размер окна по содержимому.

В июле 2026 года попытка сделать корень edge-to-edge через
`height: 100%` для `html/body` и `.shell` растянула popup в большое пустое
окно. Изменение было отменено. Поэтому:

- не переносите правила layout обычной веб-страницы в Chrome popup;
- не задавайте процентную высоту всей корневой цепочке;
- проверяйте собранное расширение через `chrome://extensions`;
- сохраняйте текущую компактную внешнюю геометрию, пока пользователь явно не
  утвердит проверенный вариант.

## D-008. Масштаб ограничен по скорости

Трекпад создаёт много wheel-событий. Масштаб меняется небольшими шагами с rate
limit и пределами, иначе текст «улетает» за одно движение.

## D-009. Тест обязателен для каждой фичи и каждого бага

Новый пользовательский сценарий должен иметь автоматический happy path и
релевантную границу. Исправление бага должно оставлять регрессионный тест с
исходным примером. Coverage — дополнительная страховка, но не замена
содержательному тесту.

Если изменение затрагивает количество API-запросов, тест должен проверять
счётчик запросов. Если затрагивает UI — тест должен проверять видимость и
состояние DOM. Если затрагивает отмену — тест должен подтвердить disconnect или
abort.

## D-010. Сначала платформа и проверенные решения

Перед новой библиотекой проверяются стандартные Web API, Chrome APIs и
существующие зрелые решения. Своя реализация допустима, когда задача мала,
специфична для Sensemark и покрыта тестами. Runtime-зависимость не добавляется
без оценки размера, лицензии, безопасности и расхода ресурсов.

## D-011. Дизайн защищён замком

Раньше AI-агент переделал внешний вид и сломал интерфейс. Поэтому файлы,
отвечающие за дизайн, зафиксированы отпечатками в `tests/design-lock.json`,
а `tests/design-lock.test.js` падает при любом их изменении.

Намеренная правка (например, анимации) принимается одной командой
`npm run design:approve`. Агенты делают это только с явного разрешения
пользователя. Логика в `content.js` замком не затрагивается — в отпечаток
входит только блок CSS карточки.

## D-012. Универсальный переводчик без привязки к сайтам

Sensemark переводит любой текст с любого языка на русский. Раньше в код,
промпт и описания попали правила под отдельный сайт (Quran.com) и отдельную
тематику — это сужало продукт и усложняло код. Они удалены.

Следствие: никаких особых веток для конкретных сайтов, тематик или текстов —
ни в очистке выделения, ни в промпте, ни в тестовых примерах, ни в описаниях.
Если сайт отображает текст нестандартно, решение должно быть общим и работать
на любом сайте.

## D-013. Случайные выделения не переводятся

Люди выделяют текст не только чтобы перевести, но и чтобы скопировать.
Выбран вариант «угадывать по поведению» без новых кликов: автоперевод ждёт
500 мс и отменяется, если за это время нажато ⌘/Ctrl+C, открыто контекстное
меню или выделение сделано в поле ввода. Для серий копирований в карточке есть
пауза на 5 минут и полное выключение автоперевода; ручной перевод правым кликом
и горячей клавишей работает всегда.

Рассмотренные альтернативы: кнопка рядом с выделением (надёжнее, но лишний
клик), перевод только с зажатой клавишей (незаметно для новых пользователей).

## D-014. Бесплатный режим по умолчанию, OpenAI — по желанию

Цель — чтобы перевод почти ничего не стоил пользователю. Бесплатного ИИ-API
без ключа нет: у Google перевод через LLM платный, неофициальные адреса
переводчиков нарушают правила сервисов и могут перестать работать в любой
момент. Поэтому по умолчанию используется встроенный переводчик Chrome
(Translator API): бесплатно, без ключа, на устройстве. OpenAI — опция «умнее»
со своим ключом. Пользователи, у которых уже есть ключ, при обновлении
остаются в режиме OpenAI.

## D-015. Модель и расход токенов

`gpt-4o-mini` и остальные старые модели OpenAI отключаются до января 2027.
По умолчанию — `gpt-6-luna` ($0.10 / $0.50 за 1M токенов), самая дешёвая
актуальная модель. Это «рассуждающая» модель: отправляем
`reasoning_effort: "none"` и `max_completion_tokens`, без `temperature`
(иначе HTTP 400 и лишние оплачиваемые токены размышлений).

Расход урезан: инструкции на английском и короче (430–550 → 170–275 токенов
на запрос), проверка ответа не бракует оставленные имена и термины (каждый
лишний repair удваивает цену), крошечные вкрапления другой письменности
(«π», «東京») не включают многоязычный формат, кэш живёт до закрытия
браузера, длина ответа ограничена. Ориентир: один перевод фразы ≈ $0.00003.

## D-016. Карточка «Хамелеон»

Карточка берёт цвет фона и текста страницы и размер её шрифта (тема «Под
страницу»); светлую или тёмную можно закрепить в настройках. Запасные цвета
стоят на `:host`, а не на `.card`: иначе они перекрывают цвета страницы и
карточка всегда белая (такой баг уже был, есть регрессионный тест).

Пока ответа нет, вместо пустой карточки показывается маленькая пилюля статуса
(12 px, приглушённый цвет), через секунду сжимается в кружок. Процент есть
только у скачивания языкового пакета; для OpenAI дуга бесконечная — честного
процента там нет. Пилюля появляется через 200 мс, чтобы не мелькать
в бесплатном режиме (~30 мс на перевод).

Длинное выделение — от 300 символов или от двух абзацев, если в них вместе от
120 символов. Оно переводится заметкой на полях справа (нужно ≥ 300 px), иначе
панелью у края окна. Боковую панель Chrome (`chrome.sidePanel`) открыть
автоматически нельзя — нужен клик, поэтому панель рисуется на странице.
На узких окнах (< 640 px) всегда карточка у выделения.

## D-017. Safari: переводчик Apple вместо Translator API

В Safari нет Translator API Chrome. Бесплатный режим там идёт через нативную
часть приложения-контейнера: `background.js` пересылает `{type: "native"}` в
`SafariWebExtensionHandler.swift`, который переводит `TranslationSession`
(без окна — только macOS 26.4+, языки должны быть уже скачаны) и определяет
язык `NLLanguageRecognizer`. `createAppleBridge` повторяет интерфейс
Translator API, поэтому движок, карточка и popup общие для двух браузеров.

Языки macOS разрешает скачивать только из окна приложения
(`.translationTask`), поэтому кнопка «Скачать» в карточке открывает
приложение Sensemark и ждёт, пока язык появится; процента там нет — кольцо
просто крутится.

Разрешение `nativeMessaging` добавляется только в Safari-манифест
(`scripts/build-safari-kit.js`): в Chrome оно дало бы лишнее предупреждение
при установке. Тест следит, чтобы его не было в `manifest.json`.

Swift-код нельзя собрать в CI (нужны macOS и Xcode): его операции сверяются
тестом с операциями моста, а сборка проверяется на Mac.
