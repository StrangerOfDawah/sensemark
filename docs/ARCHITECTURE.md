# Архитектура Sensemark

## Назначение

Sensemark — Chrome Extension Manifest V3 для перевода выделенного или вручную
введённого текста на русский. Два режима (`provider` в `chrome.storage.local`):

- `builtin` (по умолчанию) — встроенный переводчик Chrome (Translator API) на
  устройстве, без ключа и без сети;
- `openai` — свой ключ OpenAI, запрос идёт из service worker напрямую в OpenAI.

Сервера разработчика нет: настройки хранятся локально.

## Основной поток

```text
выделение или ручной ввод
        ↓
локальная очистка и определение письменностей
        ↓
локальный пропуск русского / проверка лимитов
        ↓
подготовка одного prompt и cache key
        ↓
background.js → OpenAI streaming API
        ↓
проверка протокола и содержимого ответа
        ↓
парсер ответа → карточка на странице или toolbar popup
```

## Локальная подготовка текста

`content.js` получает выделение и передаёт его в `selection-text.js`. Очистка
должна сохранить видимый смысл и убрать только доказанный шум. Очистка
универсальна: в ней нет правил под отдельные сайты или тематики.

- Мусором считаются элементы управления (кнопки, поля, `role="button"`),
  меню и навигация, шапка/подвал/боковая панель сайта вне `article`/`main`,
  сноски-ссылки в `<sup>`, скрытый текст, символы иконочных шрифтов (Private
  Use Area) и невидимые управляющие символы.
- Ссылки внутри текста — содержимое.
- Фрагменты одного блока склеиваются без лишних пробелов, разные блоки и `<br>`
  дают перенос строки.
- Если выделен только элемент интерфейса, он переводится.
- Остатки интерфейса, которые не удалось определить локально, модель
  пропускает по инструкции в промпте; второго запроса для этого нет.

После очистки `language-detection.js`:

- распознаёт семейства письменностей;
- объединяет Han, Hiragana и Katakana в японскую письменность;
- отличает русский текст от других кириллических языков;
- допускает небольшие технические латинские вставки в русском;
- не пропускает настоящий иностранный фрагмент.

Русский-only сценарий завершается здесь и не создаёт API port.

## Бесплатный режим

`builtin-translator.js` отдаёт результат в том же протоколе (`[[text]]`,
`[[translation]]`, `[[multilingual]]`), что и OpenAI, через `openLocalPort` с
интерфейсом `chrome.runtime.Port`. Поэтому `content.js` и `popup.js` не знают,
откуда пришёл перевод, и UI один.

- Язык определяется `chrome.i18n.detectLanguage`; для нелатинских письменностей
  при сомнении — по письменности.
- Смешанный текст делится на предложения; русские куски сохраняются.
- Многострочный текст переводится построчно: Translator API склеивает строки.
- Для одного слова дополнительно переводится предложение («в предложении: …»),
  так как встроенный переводчик не выбирает значение по контексту.
- Новый язык требует скачивания пакета. С жестом пользователя Chrome качает сам —
  карточка показывает статус и прогресс, таймаут 60 с. Без жеста (горячая
  клавиша, меню) карточка показывает кнопку «Скачать».
- Translator API есть только в защищённом контексте: на `http://` страницах
  показывается объяснение.

## Режимы запроса

Короткий фрагмент может идти в word mode с контекстом предложения. Остальной
текст идёт в text mode. Обнаруженные письменности входят в cache key и prompt.

Ответ модели использует внутренний протокол:

- `[[translation]]` — обычный перевод слова или короткого выражения;
- `[[reference]]` — имя, название, бренд, никнейм, опечатка или неизвестный
  термин;
- `[[text]]` — единый перевод текста;
- `[[multilingual]]` и `[[script:SCRIPT|lang:LANGUAGE]]` — отдельные
  многоязычные секции.

Короткий параллельный заголовок вроде
`Japanese Daycares – 日本の保育園` может вернуть один `[[text]]`, если обе части
выражают одно значение. Обычный многоязычный абзац обязан содержать все секции.

## Валидация и repair

`background.js` отвергает:

- `[[skip]]` из модели;
- отсутствующие обязательные секции;
- добавленные письменности, которых не было в выделении;
- повтор иностранного оригинала;
- перевод на третий язык;
- скопированные инструкции и подпись `Перевод:`.

Repair — исключительный второй запрос после конкретной ошибки. Корректный
единый перевод параллельного заголовка не должен запускать repair.

## Автоперевод и случайные выделения

Автоперевод (`content.js`) ждёт 500 мс после выделения мышью. Если за это время
нажато ⌘/Ctrl+C (по `event.code`, чтобы работало на русской раскладке), открыто
контекстное меню или произошло копирование, запрос отменяется — пока карточка
ещё не показана. Выделение в полях ввода и редакторах автоматически не
переводится.

Кнопка паузы в карточке пишет в `chrome.storage.local` `autoPausedUntil`
(пауза на 5 минут, общая для всех вкладок) или выключает `autoTranslate`.
Ручной перевод — контекстное меню выделения и горячая клавиша — работает
всегда. Пункт в меню значка расширения (`contexts: ["action"]`) включает,
выключает автоперевод или снимает паузу.

## Отображение

Страница и toolbar popup используют одни парсеры, но разные оболочки:

- карточка страницы создаётся в Shadow DOM и появляется только после видимого
  текста из стрима;
- toolbar popup существует сразу после нажатия на иконку, автоматически
  переводит вставку или ввод после debounce и отменяет устаревший stream.

Raw protocol markers никогда не должны попадать в UI.

## Кэш и жизненный цикл

Service worker держит до 200 последних результатов в памяти и копию в
`chrome.storage.session` (переживает засыпание service worker, не пишется на
диск, очищается при закрытии браузера). Ключ в кэш не попадает. Закрытие карточки или изменение ручного ввода
разрывает port и вызывает `AbortController`, чтобы не оплачивать ненужное
продолжение генерации.

## Границы безопасности

- Разрешён только `https://api.openai.com/*`.
- Inline и удалённый исполняемый код запрещены.
- API-ключ не входит в ZIP, логи, тестовые fixture или GitHub artifacts.
- Текст изображения без доступного текстового слоя не отправляется в API:
  автоматического OCR нет.
